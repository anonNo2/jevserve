# JevServe 开源完善计划

日期：2026-10-13。基线：已发布通用镜像 `anonwx/jevserve:0.1.0-dev1`，
7 个固定模型配置完成真实 GPU/容器执行；Open-Jev/JPT 存在概率偏差，
NeoHorse/Kev 仅通过小型合成对照，尚无 alpha/生产认证。

本轮目标是让外部用户能够复现结果、追溯发布版本并参与维护。
用户已授权多个 subagent 并行执行；每个 agent 仅获得所负责问题的上下文。
执行结果、实际命令和未运行门禁集中写入 `docs/development/STATUS.md`。

## 本轮并行分工

第一轮执行 O01–O04；O05–O08 保留为后续有明确验收的工作项。

- 文档 agent：O01；只修改贡献/交接/启动指南及历史计划说明，不修改运行时。
- 验证 agent：O02；只修改公开验证编排、相关 CPU 测试和使用文档，不修改现有模型适配语义。
- 发布 agent：O04；只修改发布工作流、发布验证工具/测试、CHANGELOG 和发布文档；不直接发布或改写 dev1。
- 主 agent：O03、共享资源协调、集成验证、独立交叉审查、STATUS/DECISIONS 更新及最终提交。

所有 agent 使用独立任务说明，不继承整段对话。共享工作区按文件职责划分；
发现跨职责问题先通知主 agent，避免同时编辑同一文件。子 agent 不自行提交、推送，
由主 agent 汇总为一致的提交。不得因为并行开发而并行占用同一 GPU；
GPU/容器重工作由主 agent 调度。CPU 检查可以并行。

## 不变约束

- 一个通用运行时镜像；权重独立挂载；一个容器拥有一个模型/引擎。
- 不放宽冻结的数值容差，不把标签一致当作概率认证，不静默更换精度、模型或后端。
- CPU 测试无需 GPU 包/模型下载；模型协议保留原始模板、候选顺序和温度。
- 不修改共享 Docker daemon、驱动或其他 GPU 进程；不执行全局 prune。
- 不提交模型权重、凭据、私有主机信息或 `.local/`。
- 任何新镜像/认证结论都需要对应的实际证据；已有发布不能因新增工作流被追认成稳定版。

## 完成定义

本轮交付应包括 O01/O02/O04 的可审查改动及其验证结果，O03 的诊断证据和结论，
以及仍未满足的认证/长稳/干净主机门禁。每个工作项分别标注已完成、部分完成或阻塞，
不能以计划、脚本存在或 CI 绿灯替代实际 GPU/发布结果。
